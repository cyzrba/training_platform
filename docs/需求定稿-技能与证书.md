# 技能与证书 · 需求定稿

> 状态：需求口径已锁定，尚未开工写代码。

> 来源：教师端同学聊天记录 + 李杰老师对《工业AI视觉项目落地流程（学校实用版）》的批注 + 本人最终确认。

## 一、业务链路

学生选定一个职业（目标，中途可换）→ 该职业固定对应一张证书 → 证书挂一组"所需技能点" →
每个技能点由若干项目覆盖 → 学生完成项目，点亮技能点 → 所需技能点全部点亮，证书才点亮 →
证书点亮后才能进入 AI 面试 → 面试通过后进入人工审核 → 审核通过，发放证书。

点亮顺序是严格单向的：

```text
项目完成 → 技能点（进度 100%）→ 证书点亮 → AI 面试 → 人工审核 → 发证
```

## 二、已确定的口径

1. 一个职业固定对应一张证书（1:1）。
2. 换职业后：旧的技能进度保留，旧证书保留。
3. 完成项目口径：学生自主闯关完成的项目也算；技能点的分母 = 该技能关联的全部已发布项目，
   任务下发只决定"哪些项目是老师布置的必修"，不改变技能点亮的分母分子。
4. AI 面试：题目来源、判分标准、是否可重考及次数/时间限制，本期暂不细化，先留接口占位。
5. 人工审核：审核对象（面试结果 / 学生材料 / 二者都要）本期暂不细化，先留流程占位。
6. 证书有效期：永久。
7. 审核驳回后可以重新申请（重考），已点亮的技能进度不重算。
8. 技能点绑定在项目上（项目级），教师端新建项目时可以像现在一样选择技能点、并在项目里直接创建新技能点。
   技能点不能脱离项目/岗位单独创建，不允许出现"岗位和项目两端都没绑定"的技能点。
9. 每个项目可挂多个技能点，一个技能点可被多个项目挂；点亮一个技能点 = 完成所有挂了这个技能点的项目（进度 100%）。

## 三、待老师拍板的边角问题

- 若后续给某个技能点新增了项目，分母会变大，已点亮的技能会按公式回退为未点亮。
  建议采用"点亮即固化、只进不退"，但这与字面公式略有出入，需确认。
- 之前聊天记录里提过"技能绑到项目的具体模块、按模块得分点亮"，与本次"项目级绑定 + 完成项目点亮"冲突。
  本定稿以项目级为准；模块级绑定不再纳入平台点亮逻辑。

## 四、与现有系统的对照

### 已经具备（后端）

- 项目 ↔ 技能点 多对多：`project_skill`
- 学生技能进度：`student_skill.progress = 完成项目数 ÷ 关联项目总数`，100% 即点亮
- 学生选职业、中途换职业：`student_job`（切换保留技能进度）
- 已发放证书台账：`student_certificate`（编号、名称快照、状态、作废/补发）

### 需要新增（后端）

- 证书规则：每个职业对应哪张证书（名称、发证机构、状态）
- 证书 ↔ 所需技能点：证书需要哪些技能点
- 证书点亮状态：由"所需技能点是否全部点亮"派生
- 证书申请 / 面试 / 审核 流程与状态机
- 相关接口：证书规则配置、证书条件查询、申请提交、面试占位、人工审核通过/驳回、发证

### 需要真实化（前端）

- 学生端「认证中心」：由演示数据改为真实流程
- 教师端「企业认证证书」：由演示数据改为真实数据（证书规则、审核申请、证书台账）

## 五、建议的数据模型（待实现时评审）

### 新增：证书规则

```text
certificate_rule
  id
  job_id                 → job.id（唯一，1:1）
  cert_name              证书名称
  issue_org_name         发证机构
  status                 ENABLED / DISABLED
  description            说明
  created_at / updated_at
```

### 新增：证书 ↔ 技能点

```text
certificate_skill
  id
  certificate_rule_id    → certificate_rule.id
  skill_node_id          → skill_node.id
  unique(certificate_rule_id, skill_node_id)
```

### 新增：证书申请（面试 + 人工审核流）

```text
certificate_application
  id
  student_id             → sys_user.id
  certificate_rule_id    → certificate_rule.id
  status                 PENDING_INTERVIEW / INTERVIEW_PASSED / UNDER_REVIEW / APPROVED / REJECTED
  interview_json         面试结果（题目/回答/AI 结论，本期占位）
  review_comment         人工审核意见
  reviewer_id            审核人
  student_certificate_id 通过后生成的证书记录
  submitted_at / finished_at
```

### 复用现有表

- `job`（职业）、`student_job`（选职业/换职业）、`project_skill`（项目技能）、
  `student_skill`（技能进度）、`student_certificate`（发证台账）、`skill_node`（技能点，含描述字段）
