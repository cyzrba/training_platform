## 3. 数据库适配策略（PostgreSQL → SQLite）

原 DDL 面向 PostgreSQL 15+，落到 SQLite 需逐项处理，否则会出现"看起来建好了、写入即报错"的坑：

| PG 特性 | SQLite 方案 | 备注 |
| --- | --- | --- |
| `bigint GENERATED BY DEFAULT AS IDENTITY` | `BigInteger().with_variant(Integer, "sqlite")` + `autoincrement=True` | **关键**：SQLite 只有 `INTEGER PRIMARY KEY` 才是 rowid 别名，直接写 BIGINT 主键自增会失效 |
| `timestamptz` | 自定义 `TZDateTime(TypeDecorator)`，落库 ISO8601 UTC 字符串，Python 侧保持 tz-aware | 避免 SQLite 丢时区。全平台统一存 UTC，展示层转本地 |
| `jsonb` | SQLAlchemy `JSON`（TEXT 存储），代码里统一用别名 `JSONB` | 切回 PG 只需改别名映射，模型零改动 |
| `numeric(5,2)` | `Numeric(5,2, asdecimal=True)` → 存 REAL | SQLite 无定点数，靠 Pydantic 校验 + 领域层量化保证精度 |
| `date DEFAULT CURRENT_DATE` | `server_default=func.current_date()` | 兼容 |
| 部分唯一索引 `WHERE ...` | `Index(..., unique=True, sqlite_where=text("..."))` | SQLite 3.8+ 支持；注意通用参数是 `where=`、SQLite 专用是 `sqlite_where=` |
| `CHECK` 约束 | 原生支持 | `chk_skill_node_not_self`、`difficulty 1~5` 原样保留 |
| `COMMENT ON TABLE` | SQLite 不支持 → 用 `Table(comment=...)` + 模型 docstring | 注释不落库，仅元数据与文档用途 |
| 外键约束 | 默认关闭 → engine `connect` 事件执行 `PRAGMA foreign_keys=ON` | 不开则外键形同虚设 |
| 并发写入 | `PRAGMA journal_mode=WAL`、`synchronous=NORMAL`、`busy_timeout=5000`，`check_same_thread=False` | SQLite 单写多读；写操作串行 |
| 唯一约束中的 NULL | SQLite 与 PG 一致（NULL 互不相等） | 多条自定义模块（`stage_key` 为空）可共存，语义不变 |

连接串：`sqlite+aiosqlite:///./data/app.db`（可通过 `.env` 覆盖为内存库用于测试）。

## 4. 模型设计（38 张表）

### 4.1 公共基类与规范

- `Base`：`DeclarativeBase`，统一命名约定，表名/列名与 DDL 完全一致（snake_case）。
- `TimestampMixin`：`created_at`、`updated_at`（`TZDateTime`，`server_default=now()`，`onupdate=now()`）。
- `SoftDeleteMixin`：`deleted_at`，仅主数据表使用；仓储层默认过滤未删除记录。
- 枚举：`app/models/enums.py` 用 `StrEnum` 定义、落库仍为 `varchar`（`native_enum=False`），取值严格对应附录 A。
- 关系：按需声明 `relationship()`（如 `student_project → attempts → stages`），FK 全部保留 `ondelete` 语义（软删表用 `RESTRICT`）。

### 4.2 分域清单（模型文件 ↔ 表 ↔ 数量）

| 域 | 模型文件 | 表 |
| --- | --- | --- |
| A 账户与权限（6） | `a_account.py` | `sys_user`、`sys_role`、`sys_permission`、`sys_user_role`、`sys_role_permission`、`system_config` |
| B 教学组织（4） | `b_org.py` | `class_info`、`class_group`、`class_student`、`class_student_group` |
| C 岗位与技能（9） | `c_job_skill.py` | `job`、`student_job`、`skill_tree`、`skill_node`、`skill_node_dependency`、`student_skill`、`job_skill`、`growth_rule`、`project_skill` |
| D 实训项目（3） | `d_project.py` | `training_project`、`project_stage_template`、`project_module` |
| E 闯关与评审（8） | `e_attempt_review.py` | `file_asset`、`student_project`、`training_attempt`、`attempt_stage`、`attempt_stage_file`、`project_submission`、`review_record`、`review_ai_job` |
| F 证书台账（1） | `f_certificate.py` | `student_certificate` |
| H AI 知识库（5） | `h_ai_kb.py` | `knowledge_doc`、`knowledge_chunk`、`ai_qa_session`、`ai_qa_message`、`ai_qa_citation` |
| I 通知与审计（2） | `i_notify_audit.py` | `notification`、`operation_log` |

> 注意：`project_skill` 在 DDL 中因依赖 `training_project` 而后置创建，ORM 中按域归到 C 域文件，靠 metadata 的依赖排序解决，不影响 DDL 与清单的一致性。

### 4.3 必须原样落地的约束

- 唯一约束 30 个（29 个具名 `uk_*` + `class_student_group.class_student_id` 列级 UNIQUE）。
- 唯一索引 3 个，均为部分索引：`uk_sys_user_ext`、`uk_class_student_active`、`uk_student_job_primary`。
- 普通索引 30 个，其中 `idx_project_submission_starred` 为部分索引（`WHERE is_starred`），多张表含 `DESC` 排序索引。
- CHECK 约束 2 个：`chk_skill_node_not_self`、`chk_training_project_difficulty`。
- 外键 57 条，与附录 B 对应。
- 以上名称全部与 DDL 保持一致，便于 `check_schema_parity.py` 自动比对（上述数字已按 DDL 原文统计）。

## 5. Schema（Pydantic v2）设计

### 5.1 公共模型

| 模型 | 用途 |
| --- | --- |
| `ORMModel` | `model_config = ConfigDict(from_attributes=True)` 基类 |
| `TimestampRead` / `SoftDeleteRead` | 时间戳、软删字段复用块 |
| `PageParams` | `page`、`page_size`、`order_by`、`desc` |
| `Page[T]` | 泛型分页响应 `{items, total, page, page_size, pages}` |
| `IdListIn` | 批量操作入参（如批量加人、批量启停） |

### 5.2 每张表 4 个模型

- `XxxBase`：共有业务字段 + 枚举 + 长度/范围校验（`Field(max_length=...)`、`condecimal`、`ge/le`）。
- `XxxCreate`：必填字段；`id`、时间戳、软删字段不出现。
- `XxxUpdate`：全部字段 `Optional`，配合 `model_dump(exclude_unset=True)` 做部分更新。
- `XxxRead`：含 `id`、时间戳、软删标记，继承 `ORMModel`，直接 `from_orm` 输出。

特殊表按业务加派生模型，例如：

- `sys_user`：`UserCreate`、`UserUpdate`、`UserRead`、`UserBrief`、`UserWithRoles`。
- `training_project`：增加 `ProjectWithModules`（含 `project_module` 列表与 `project_skill` 技能点）。
- `project_submission`：增加 `SubmissionDetail`（提交 + 模块作答 + 附件 + 评审记录）。
- `review_record`：`dimension_json` 用 `list[DimensionScore]` 强类型建模，而不是裸 `dict`。
- 分数类字段统一 `condecimal(max_digits=5, decimal_places=2)` + 业务范围校验（0~100）。

### 5.3 一致性保障

手写 schema，同时提供 `tests/test_schema_parity.py`：

1. 遍历 ORM metadata 的每张表/每个字段，断言其在 `数据库表字段清单.md` 中存在且类型族一致；
2. 断言 38 张表的 `XxxCreate/XxxUpdate/XxxRead` 均已定义且字段覆盖完整（排除自增主键与时间戳）；
3. 断言枚举取值集合与附录 A 完全相同。

这样后续改表时，漏改 schema 会被测试直接拦下。
