## 2. 全局处理器怎么工作的

一次请求只有两条出路：**正常返回**（包成 `{code:200, data, msg:"ok"}`）或**异常**（翻译成 `{code:422|500, data, msg}`）。
兜底入口只有一个 `EnvelopeRoute`；`register_exception_handlers` 是接住路由之外异常的第二道网。

```mermaid
flowchart TD
    START(["HTTP 请求进入"]) --> CORS["CORSMiddleware"]
    CORS --> ER["EnvelopeRoute.get_route_handler()<br/>（每个业务路由都挂了它）"]
    ER --> TRY{"try: 执行端点<br/>依赖注入 → 仓储/服务 → 业务逻辑"}

    TRY -->|"正常 return 业务数据"| SER["FastAPI 用 response_model 校验<br/>ApiResponse[X]<br/>before 校验器自动包壳"]
    SER --> WRAP["wrap_success 兜底<br/>已是统一结构则放行"]
    WRAP --> CHK{"Content-Type 是 JSON?"}
    CHK -->|是| OK["HTTP 200 / 201<br/>{code:200, data, msg:'ok'}"]
    CHK -->|"否（xlsx 等文件流）"| RAW["原样透传二进制<br/>不包壳"]

    TRY -->|"抛 AppError<br/>NotFound/Conflict/BusinessRule"| EA["error_response(exc)"]
    TRY -->|"抛 RequestValidationError<br/>参数/路径校验失败"| EA
    TRY -->|"抛 HTTPException<br/>404 未知路径 / 405 方法不允许"| EA
    TRY -->|"抛其它 Exception（未预期）"| EA

    EA --> KIND{"异常类型"}
    KIND -->|"前三类"| F422["HTTP 200<br/>{code:422, data:明细, msg:错误提示}"]
    KIND -->|"未预期"| F500["HTTP 500<br/>{code:500, data:null, msg:通用提示}<br/>堆栈只进服务端日志"]

    CORS -. "异常发生在路由之外<br/>（中间件 / 框架层）" .-> GLOBAL["register_exception_handlers<br/>AppError · HTTPException · Validation · Exception"]
    GLOBAL --> EA

    OK --> FIN(["返回给调用方"])
    RAW --> FIN
    F422 --> FIN
    F500 --> FIN
```

### 关键约定

| 关注点 | 位置 | 说明 |
| --- | --- | --- |
| 成功包壳 | `schemas/base.py::ApiResponse[T]` | 端点照旧返回业务数据，`before` 校验器把它包成统一结构，`/docs` 的响应模型与真实返回一致 |
| 异常兜底 | `core/response.py::EnvelopeRoute` | 每个业务路由的路由类，`try/except` 只写这一处，44 个端点全覆盖、不会漏 |
| 异常翻译 | `core/response.py::error_response` | 四类异常统一出口：业务异常 / 参数校验 / HTTP 异常 / 未预期异常 |
| 第二道网 | `core/exceptions.py::register_exception_handlers` | 路由之外（中间件、依赖解析前）抛的异常也走同一出口 |
| 非 JSON 放行 | `core/response.py::wrap_success` | Excel 模板下载等文件流按 Content-Type 跳过包壳 |
| HTTP 状态 | `core/response.py::FAILURE_HTTP_STATUS` | 当前业务失败 = HTTP 200（只看 body 的 code）；未预期异常 = HTTP 500 |

### 请求示例

```bash
# 成功
curl -s http://127.0.0.1:8000/api/health
# {"code":200,"data":{"ok":true,...},"msg":"ok"}   HTTP 200

# 业务失败：找不到
curl -s http://127.0.0.1:8000/api/users/99999
# {"code":422,"data":null,"msg":"用户 99999 不存在"}   HTTP 200

# 参数校验失败：明细在 data
curl -s http://127.0.0.1:8000/api/users/abc
# {"code":422,"data":[{"loc":["path","user_id"],...}],"msg":"请求参数校验失败"}   HTTP 200

# 文件流：不包壳
curl -sI http://127.0.0.1:8000/api/classes/students/import-template
# content-type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
```

## 3. 数据流：教师端建班导学

```mermaid
sequenceDiagram
    autonumber
    participant T as 教师端
    participant API as EnvelopeRoute + accounts/organization
    participant SVC as services/student_import
    participant DB as SQLite

    T->>API: POST /api/classes 建班级
    API->>DB: insert class_info
    API-->>T: {code:200, data:{id:1,...}, msg:"ok"}

    T->>API: POST /api/classes/1/groups 建分组
    API->>DB: insert class_group
    API-->>T: {code:200, data:{group_no:1}, msg:"ok"}

    T->>API: GET /api/classes/students/import-template
    API-->>T: xlsx 字节流（不包壳）

    T->>API: POST /api/classes/1/students/import (dry_run=true)
    API->>SVC: 解析 + 整批校验
    SVC-->>API: 预检统计
    API-->>T: {code:200, data:{dry_run:true,...}, msg:"ok"}

    T->>API: POST /api/classes/1/students/import (dry_run=false)
    API->>SVC: 解析 + 校验（有问题则整批拒绝）
    alt 校验不通过
        API-->>T: {code:422, data:[{row,user_no,reason}], msg:"名单校验未通过"}
    else 校验通过
        SVC->>DB: 建 sys_user（默认密码哈希）+ class_student + class_student_group
        API-->>T: {code:200, data:{created_users:3,...}, msg:"ok"}
    end
```
